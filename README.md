# RTA (ṚTA) — доказать факт, не раскрыв его

## Почему так называется

**Ṛta** — центральное понятие ведической космологии: **порядок, истина и
правильное соответствие между действием и следствием**.

Работа ZK-доказательства — это ровно Ṛta. Проверяющий не спрашивает
«похоже ли на правду». Он убеждается, что **следствие следует из действия
по правилу, и никакого иного варианта не существует**. Одно утверждение —
одна истина. В ведическом языке это называется словно: `ṛta` управляет тем,
что события идут в правильном порядке и дают правильный результат.

## Правило именования: единый пантеон

Имена продуктов берутся **из одного пантеона — ведического**, потому что
агент ИндрА ведический, система называется «Божественная канцелярия» и
работа идёт в рамках карма-йоги. Смешивать пантеоны нельзя: греческая
Ананке рядом с ведическим ИндрА — это как звать соседа по имени в чужом
храме.

**Отвергнуто с причинами, чтобы не предлагали заново:**
- **Гекате** — по функции ближе всех (ключи от ворот, распутье, скрытое
  знание), но комплаенс-офицеру банка «Hecate» звучит как оккультизм.
  Это риск сделки, а не вкус.
- **Варуна** — в ведическом пантеоне и по смыслу сильнее (его петля́
  настигает скрытое: «Ригведа» 1.24), но `Varuna Integrity Services` —
  компания по аудиту безопасности. **Прямая коллизия в нашей нише.**
- **Агни** — огонь-испытание, тоже ведический, но крипто-коллизия (AgniCash).
- **Ананке** — греческая, нарушала единый пантеон.
- **Hermes** — нейтрально, но тяжёлый товарный знак.
- **Janus** — прямое столкновение: Janus Software / JanusSecurity, старая
  антивирусная компания. В безопасности путается.
- **Nox / Nyx** — только сокрытие, ничего о доказательстве.

**Честная цена выбора:** `ṛta` на слух читается как «ритах», непривычно.
Объяснять придётся нам, а не рынку. Смягчает то, что имя нейтральное —
ни оккультизма, ни религиозной нагрузки.

`rta` занят в npm. Для продукта, распространяемого через GitHub, это не
помеха; при выходе в реестры — область `@mrpkk/rta`.

Первый работающий модуль: **настоящее ZK-доказательство Groth16**, собранное
локально, без бюджета, без внешней церемонии и без платных сервисов.

## Что уже работает

Схема доказывает одно утверждение: **«возраст >= 18»** — и не раскрывает
ни возраст, ни дату рождения.

| Проверка | Результат |
|---|---|
| Возраст 18, 21, 37, 100, 255 — доказательство принимается | ok |
| Возраст 0, 5, 16, 17 — доказать **нельзя** | ok |
| Публичные сигналы доказательства | пустые `[]` |
| Публичные данные зависят от возраста | нет — одинаковые для 18, 40 и 200 |
| Подменённый verification key | отклоняется |
| Размер доказательства | **723 байта** |

Итог испытаний: **12 ok, 0 FAIL** (`node build/test.js`).

### Почему «доказать нельзя» важнее «доказать можно»

Проверяющий видит только 723 байта и одно слово «верно». Он **не может**
отличить 18 от 100 — публичные данные пусты. И он не может получить
доказательство для 17 лет: ограничение невыполнимо, свидетельство не
собирается, а значит **ложь опровержима, а не просто недоказуема**.

## Как это устроено

Возраст раскладывается на 8 бит, и разность `возраст − 18` тоже
раскладывается на 8 бит. Из равенства
`сумма(биты разности) = возраст − 18` следует, что разность неотрицательна:
отрицательное число в двоичной записи из 8 неотрицательных бит не помещается.

```circom
accAge  === age;            // возраст = сумма своих битов
accAge - 18 === accDiff;   // разность = сумма своих битов
```

Схема: `circuits/age.circom`. Сборка всех артефактов: `build/setup.sh`.

## ⚠️ Чего этот стенд НЕ делает

| Не сделано | Почему это важно |
|---|---|
| **Церемония односторонняя** | Участник один, значит toxic waste известен ему. Подделка доказательств возможна. **Риск №1, не закрыт.** См. `build/VERIFY.md` |
| Нет HTTP-сервиса | Есть только библиотека и испытания. Клиент по сети не обратится. |
| Нет приёма оплаты | x402 не подключён, доказательство бесплатно |
| Только предикат «возраст >= 18» | Баланс ≥ X, санкционный статус, резидентство — не сделаны |
| Нет защиты от повтора | Одно и то же доказательство можно предъявлять дважды |
| Нет внешнего аудита схемы | Схема написана нами и нами же проверена |

**Про powers of tau:** параметры сгенерированы локально с детерминированной
энтропией. Для стенда этого достаточно, для продакшна — нет.

## Как собрать с нуля

```bash
export PATH="$HOME/.cargo/bin:$PATH"
bash build/setup.sh      # схема -> ключи (2-3 минуты)
node build/test.js       # испытания
```

Требуется `circom` 2.2.3 (собран из исходников через cargo) и `snarkjs`.
npm-пакет `circom@0.5.46` непригоден: его парсер теряет переводы строк и
не собирает ни одну схему. Проверено 07.10.2026.

## Проверено первыми руками, а не по документации

- `circom` из npm — сломан (парсер).

  Используется API `snarkjs.groth16.fullProve` напрямую.

Каждая из этих ошибок стоила времени и ни одна не видна в документации.
