# PROGRESS — ṚTA

> Правило: каждый шаг — **вертикальный слайс** (реализация + тест + зелёный прогон + коммит + push).
> Старт сессии: читать этот файл → взять первый незакрытый `- [ ]` → выполнить → обновить чекбокс → commit + push.
> Команда верификации: `python3 -m pytest -q` (49 passed) и `node build/verify-service.mjs` для проверки доказательств.
> Закрытый слайс = зелёный тест + коммит с хешем. Иначе не закрыт.

**Текущее состояние (09.10.2026):** 49 тестов зелёные. Пять схем Groth16 компилируются и проверяются, у каждой свой ключ. HTTP-сервис отвечает, платёжный путь прогнан **вживую на Base Sepolia**: челлендж → подпись EIP-712 → разбор фасилитатором → проверка подписи → ончейн-проверка баланса. Останавливается на `invalid_exact_evm_insufficient_balance` — то есть не хватает только USDC на тестовом кошельке. Всё остальное в цепочке работает.

Файл создан 09.10.2026 — до этого прогресса не существовало, хотя правило требовало его с самого начала. Это и было причиной, почему состояние продукта приходилось восстанавливать по коду и логам.

## Спринт 3 · Платёжный путь вживую ✅ закрыт 09.10.2026

- [x] Полный цикл на Base Sepolia доведён до ончейн-проверки баланса
- [x] Тестовый кошелёк пополнен на 20 USDC
- [x] **Расчёт проведён до успеха** — транзакция в блоке 47921360, статус
      успех, 85 780 газа. Балансы сошлись: плательщик 20 → 18, получатель
      0 → 2. Проверено в блокчейне, не по ответу сервера.
- [x] Квитанция: клиент получает `X-Payment-Response` с хешем транзакции
- [x] **Повторное предъявление отвергнуто**, HTTP 409, лишнего списания нет.
      Отсекается локально, до обращения к фасилитатору
- [x] Публичные сигналы доказательства — **ноль**. Проверяющий не узнаёт
      ничего: измерено на реальном доказательстве, а не заявлено

**Проверено вживую против сети, а не по ответу сервера:**

| Что | Как мерилось |
|---|---|
| Деньги реально переместились | `balanceOf` плательщика и получателя через web3 |
| Транзакция существует | receipt по хешу, статус `1`, номер блока |
| Повтор не проходит | второй `POST /v1/verify` с тем же nonce → 409 |
| Приватность соблюдена | `publicSignals` в доказательстве: 0 элементов |

**Что вскрылось и было исправлено попутно:**
- повтор отсекался фасилитатором, а не нами: лишний сетевой вызов на
  заведомо отвергаемый запрос;
- ускоритель схемы ждёт три входа (`secret`, `secretBits`, `diffBits`);
- один прогон дал «успех» с транзакцией, которой в блокчейне нет. Отсюда
  правило: расчёт считается состоявшимся только если транзакция найдена
  в сети и балансы сошлись.
